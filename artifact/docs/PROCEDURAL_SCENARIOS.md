# Procedural Scenario Generation

This repository trains on generated privilege-escalation scenarios and keeps the
static benchmark for evaluation. The procedural generators provide varied,
seeded tasks while preserving a clean train/eval split for the paper results.

## Source Of Truth

Generator behavior is config-driven:

- `conf/generators/training.yaml` selects the training generator profile.
- `conf/generators/holdout.yaml` selects the procedural validation/evaluation
  profile.
- Per-generator settings live under `conf/generators/training/` and
  `conf/generators/holdout/`.
- GTFOBins-derived allowlists live under `conf/gtfobins/`.
- The procedural Docker image recipe is `docker/procedural/`.
- Static benchmark exclusions and scan rules live in
  `src/generators/holdout_manifest.py`.
- The split/leakage audit bundle is generated by `src/dataset/privesc/audit.py`
  with `conf/experiment/audit/split_leakage.yaml`.

The docs intentionally summarize the split policy rather than duplicating the
full allowlists. Reviewers should treat the checked-in configs as the auditable
definition of the exact experiment surfaces.

## Generator Families

The paper-facing procedural mix covers these vulnerability families:

- GTFOBins-based SUID, sudo, and file-capability escalations
- cron wildcard and writable-script misconfigurations
- readable credential artifacts and shell-history credentials
- password reuse and weak privileged-account credentials
- SSH key reuse

Each generated scenario records a setup script, metadata, and validation
solution commands. At runtime, the harness installs a hidden root proof in the
container; generators do not expose that proof in scenario metadata.

## Split Policy

Training trace collection uses the `training` profile. Procedural validation,
SFT validation assembly inputs, and procedural evaluation use the `holdout`
profile. The profiles use deterministic seeds and disjoint configured value
pools so that validation is not merely a replay of training strings.

Static benchmark scenarios are not used for training. They are reserved for the
paper's final transfer evaluation.

## Reproducibility

Scenario generation is deterministic for a given generator key and seed. The
collection scripts use separate reserved seed ranges for training and
validation, and dataset assembly performs collision checks before writing the
final SFT dataset.

Relevant checks:

```bash
bash docker/procedural/build.sh
uv run pytest -q test/procedural/test_holdout_leakage.py
uv run pytest -q test/procedural
PRIVESC_SCENARIO_BACKEND=local_docker uv run pytest -q test/test_solutions.py
```

The full trace collection, SFT, RL, and static-evaluation workflow is described
in `docs/PAPER_REPRODUCTION_RUNBOOK.md`.
